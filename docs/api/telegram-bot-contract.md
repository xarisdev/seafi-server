# Контракт API для Telegram-бота

Документ описывает фактический HTTP/WebSocket API сервера для клиентской интеграции. Контракт основан на текущей реализации; некоторые операции доступны только внутреннему доверенному клиенту и не должны напрямую вызываться пользователем.

## Подключение и авторизация

Базовый префикс: `/api/v1`.

Все HTTP-маршруты, кроме Lava webhook, требуют заголовок:

```http
X-Api-Key: <X_API_KEY>
```

Значение берётся из настройки сервера `X_API_KEY`. Lava webhook использует тот же заголовок, но сверяет его с отдельным секретом `LAVA_WEBHOOK_SECRET`. WebSocket не использует этот HTTP-заголовок: его ключ передаётся параметром `secret_key`.

Тела запросов и ответов — JSON, если не указано иное. Даты и время передаются в ISO 8601 с часовым поясом UTC, например `2026-11-04T12:30:00Z`. Пустой успешный ответ имеет статус `204` и не содержит тела.

### Идентификация пользователя

Ряд методов принимает пользователя через query string. Нужно передать один из параметров:

```text
?telegram_id=123456789
?id=42
```

`telegram_id` — Telegram ID пользователя, `id` — внутренний ID пользователя в API. Если переданы оба, сервер использует `id`. Если не передан ни один, сервер возвращает ошибку `400`. Если пользователь не найден — `404`.

## Основные схемы

### Пользователь

Создание — `POST /users`:

```json
{
  "telegram_id": 123456789
}
```

Ответ `User`:

```json
{
  "id": 42,
  "telegram_id": 123456789,
  "created_at": "2026-11-04T12:30:00Z"
}
```

### Тарифный план

```json
{
  "id": 7,
  "offer_id": "provider-offer-id",
  "title": "Название тарифа",
  "description": "Описание",
  "amount": "10.00",
  "duration": 720,
  "created_at": "2026-11-04T12:30:00Z"
}
```

`duration` — длительность в часах. `amount` возвращается строкой с двумя десятичными знаками.

### Счёт

```json
{
  "id": 19,
  "plan_id": 7,
  "user_id": 42,
  "contract_id": "provider-contract-id",
  "payment_url": "https://...",
  "status": "pending",
  "currency": "USD",
  "amount_total": "10.00",
  "created_at": "2026-11-04T12:30:00Z"
}
```

Допустимые `status`: `pending`, `failed`, `cancelled`, `completed`. Допустимая `currency`: `USD`, `RUB`.

### Подписка

```json
{
  "id": 31,
  "user_id": 42,
  "plan_id": 7,
  "invoice_id": 19,
  "created_at": "2026-11-04T12:30:00Z",
  "started_at": "2026-11-04T12:30:00Z",
  "expires_at": "2026-12-04T12:30:00Z",
  "source": "webhook"
}
```

`plan_id`, `invoice_id`, `started_at` и `expires_at` могут быть `null`. Новая подписка, созданная промокодом, имеет `invoice_id: null` и `source` вида `promo:CODE`. Если промокод продлевает уже активную подписку, endpoint возвращает эту существующую запись: её `source` и `invoice_id` остаются прежними.

### Фильтр

```json
{
  "id": 13,
  "user_id": 42,
  "city": "bishkek",
  "ads_type": "rent",
  "ads_owner": "any",
  "min_price": null,
  "max_price": null
}
```

Допустимые значения: `ads_type`: `rent`, `sell`; `ads_owner`: `agent`, `owner`, `any` либо `null`. `city` — строка; цены могут быть целыми числами или `null`.

## Маршруты для бота

### Пользователи

| Метод и путь | Параметры/тело | Успех | Назначение |
| --- | --- | --- | --- |
| `POST /users` | JSON `{"telegram_id": int}` | `201 User` | Создать пользователя |
| `GET /users?telegram_id={telegram_id}` | query `telegram_id` или `id` | `200 User` | Получить пользователя |
| `GET /users/{telegram_id}` | path `telegram_id` | `200 User` | Получить пользователя по Telegram ID |

Повторное создание пользователя с тем же `telegram_id` возвращает `409`.

### Тарифы и продукты Lava

| Метод и путь | Параметры/тело | Успех | Назначение |
| --- | --- | --- | --- |
| `GET /plans` | — | `200 Plan[]` | Список тарифов |
| `GET /plans/{plan_id}` | path `plan_id` | `200 Plan` | Получить тариф |
| `GET /lava-products` | — | `200 Product[]` | Получить продукты платёжного провайдера |

Публичный для внутреннего API `Product` содержит `id`, `title`, `description`, `offer_id`, `offer_name`, `offer_description`. Строки описаний могут быть `null`. Если продукты не найдены, сервер возвращает `404`.

Создание и изменение тарифов (`POST /plans`, `PATCH /plans/{plan_id}`) сейчас также доступны под общим `X-Api-Key`. Это операции управления, а не пользовательский поток бота.

### Оплата и счета

Все перечисленные методы требуют идентификатор пользователя, кроме чтения и отмены счёта по ID.

| Метод и путь | Параметры/тело | Успех | Назначение |
| --- | --- | --- | --- |
| `POST /payments/invoices?telegram_id={id}&plan_id={plan_id}` | query `plan_id`, `telegram_id` или `id`; опционально `currency` (`USD` или `RUB`, по умолчанию `USD`) | `201 Invoice` | Создать платёжный счёт; ответ включает `payment_url` для оплаты |
| `GET /payments/invoices?telegram_id={id}` | query `telegram_id` или `id`; опционально `status` | `200 Invoice[]` | Список счетов пользователя, необязательно отфильтрованный статусом |
| `GET /payments/invoices/{invoice_id}` | path `invoice_id` | `200 Invoice` | Получить состояние счёта; сервер может запросить актуальное состояние у Lava и выдать подписку при подтверждённой оплате |
| `POST /payments/invoices/{invoice_id}/cancel` | path `invoice_id` | `204` | Отменить ожидающий счёт |

Создать счёт нельзя, если у пользователя уже есть активная подписка или недавний незавершённый счёт (окно — 15 минут): в обоих случаях сервер возвращает `400`. Новые счета создаются со статусом `pending`; подписка активируется после подтверждения платежа через webhook или при проверке счёта.

Переадресации платёжного провайдера:

| Метод и путь | Обязательные query-параметры | Ответ |
| --- | --- | --- |
| `GET /payments/redirect/success` | `invoiceId`, `status` | `200 {"status": "...", "invoice_id": "..."}` |
| `GET /payments/redirect/failure` | `invoiceId`, `status` | `200 {"status": "...", "invoice_id": "..."}` |
| `GET /payments/redirect/cancel` | `invoiceId`, `status` | `200 {"status": "...", "invoice_id": "..."}` |

Эти handlers только возвращают переданные query-параметры и не являются подтверждением платежа или источником состояния подписки.

### Подписки

| Метод и путь | Параметры | Успех | Назначение |
| --- | --- | --- | --- |
| `GET /subscriptions/active?telegram_id={id}` | query `telegram_id` или `id` | `200 Subscription` или `200 null` | Получить активную подписку пользователя |
| `GET /subscriptions/all?telegram_id={id}` | query `telegram_id` или `id` | `200 Subscription[]` | Получить все подписки пользователя |
| `GET /subscriptions/{subscription_id}` | path `subscription_id` | `200 Subscription` | Получить подписку по внутреннему ID |

Подписка активна, пока её `expires_at` находится в будущем. При успешной оплате `source` равен `webhook` или `lava` в зависимости от способа подтверждения.

Фильтр хранится независимо от подписки. Его наличие означает, что пользователь настроил поиск; объявления отправляются только при активной подписке. Объявления, опубликованные до начала подписки, не отправляются.

### Промокоды

| Метод и путь | Параметры/тело | Успех | Назначение |
| --- | --- | --- | --- |
| `POST /promocodes` | JSON промокода | `201 Promocode` | Создать промокод; внутренний административный метод |
| `GET /promocodes` | — | `200 Promocode[]` | Список промокодов; внутренний метод |
| `GET /promocodes/{code}` | path `code` | `200 Promocode` | Получить промокод |
| `POST /promocodes/{code}/activate?telegram_id={id}` | query `telegram_id` или `id` | `200 Subscription` | Применить промокод пользователю |

Пример создания:

```json
{
  "code": "WELCOME",
  "plan_id": 7,
  "duration_hours": 48,
  "usage_limit": 100,
  "expires_at": "2026-12-01T00:00:00Z"
}
```

Ответ `Promocode`:

```json
{
  "id": 5,
  "code": "WELCOME",
  "plan_id": 7,
  "duration_hours": 48,
  "usage_limit": 100,
  "expires_at": "2026-12-01T00:00:00Z",
  "created_at": "2026-11-04T12:30:00Z"
}
```

`plan_id`, `duration_hours`, `usage_limit`, `expires_at` необязательны. Код нормализуется в верхний регистр. `null` для `usage_limit` и `expires_at` означает отсутствие соответствующего ограничения.

При активации:

- пользователь не может применить один и тот же промокод дважды (`409`);
- истёкший промокод, исчерпанный лимит или конфликт с незавершённым счётом дают `400`;
- если у пользователя есть активная подписка, промокод продлевает её на `duration_hours`, либо на 24 часа, если срок не задан;
- если активной подписки нет, у промокода должен быть `plan_id`; новая подписка действует `duration_hours` либо срок тарифа, если длительность промокода не задана.

## Внутренние интеграции

### Lava webhook

`POST /webhook/lava` вызывается платёжным провайдером, а не ботом. Требует `X-Api-Key` со значением настройки `LAVA_WEBHOOK_SECRET`. Обработчик ожидает JSON с полями `eventType`, `contractId`, `buyer.email`, `status`, `timestamp`; `errorMessage` необязателен. Пример события:

```json
{
  "eventType": "payment.success",
  "contractId": "provider-contract-id",
  "buyer": {
    "email": "user_123456789@example.test"
  },
  "status": "success",
  "timestamp": "2026-11-04T12:30:00Z"
}
```

Endpoint отвечает `200` после передачи payload обработчику. Для подтверждения результата боту следует читать состояние счёта и подписки, а не вызывать webhook самостоятельно.

### Ручное управление подписками

`POST /subscriptions/manual/create` и `PATCH /subscriptions/manual/{subscription_id}` исключены из OpenAPI и сейчас возвращают `null` без выполнения операции. Не используйте их в интеграции.

Методы активации/деактивации фильтра также скрыты из OpenAPI и сейчас являются заглушками; боту не следует на них опираться.

## Фильтры

| Метод и путь | Параметры/тело | Успех | Назначение |
| --- | --- | --- | --- |
| `POST /filters?telegram_id={id}` | query `telegram_id` или `id`; тело не требуется | `200 Filter` | Создать фильтр пользователя |
| `GET /filters/user?telegram_id={id}` | query `telegram_id` или `id` | `200 Filter` | Получить фильтр пользователя |
| `GET /filters/{id}` | path ID фильтра | `200 Filter` | Получить фильтр по ID |
| `PATCH /filters/{id}` | частичный JSON `FilterUpdate` | `204` | Изменить переданные поля фильтра |

Пример частичного изменения:

```json
{
  "city": "osh",
  "ads_type": "rent",
  "ads_owner": "owner",
  "min_price": 10000,
  "max_price": 50000
}
```

Методы активации/деактивации фильтра в текущей реализации скрыты из OpenAPI и являются заглушками; боту не следует на них опираться.

## WebSocket

Подключение: `ws(s)://<host>/api/v1/ws/connect?secret_key=<X_WSS_KEY>`.

Клиент может отправить текстовое сообщение `ping`; сервер ответит `pong`. Неверный ключ закрывает соединение с кодом `1008`. Сервер отправляет JSON-события.

Событие объявления:

```json
{
  "type": "advertisement",
  "delivery_id": 55,
  "telegram_id": 123456789,
  "advertisement": {
    "id": 88,
    "ads_id": "117852552",
    "ads_source": 3,
    "url": "https://lalafo.kg/bishkek/ads/example-id-117852552",
    "title": "Квартира долгосрочно",
    "price": 35000,
    "city": "bishkek",
    "type": "rent",
    "owner": "agent",
    "created_at": "2026-11-04T12:30:00Z",
    "last_seen_at": "2026-11-04T12:30:00Z",
    "published_at": "2026-11-03T20:10:00+06:00"
  }
}
```

После отправки объявления в Telegram бот подтверждает результат:

```http
POST /api/v1/deliveries/55/ack
X-Api-Key: <X_API_KEY>
Content-Type: application/json
```

```json
{
  "telegram_id": 123456789,
  "success": true,
  "error": null
}
```

Успешный ACK возвращает `204`; неверный `telegram_id` — `403`, неизвестный `delivery_id` — `404`. При `success: false` сервер повторяет отправку, максимум пять попыток. ACK lease истекает через три минуты, но возврат в очередь выполняется в следующем пятиминутном цикле. ACK может быть повторён: уже отправленная запись останется `sent`.

Событие критической ошибки (только если на сервере задан `ADMIN_TELEGRAM_ID`):

```json
{
  "type": "admin_alert",
  "telegram_id": 123456789,
  "source": "general-agency",
  "message": "Lalafo source parsing failed",
  "created_at": "2026-11-04T12:30:00Z"
}
```

## Ошибки и ограничения текущей реализации

Обычно FastAPI возвращает ошибки в формате:

```json
{
  "detail": "Описание ошибки"
}
```

Часто используемые статусы: `400` — некорректное состояние/запрос; `401` — отсутствует API-ключ; `403` — неверный API-ключ; `404` — объект не найден; `409` — конфликт/повторное создание или использование; `422` — ошибка валидации запроса. Для `422` FastAPI может вернуть массив ошибок в `detail`.

Перед интеграцией учитывайте следующие текущие ограничения:

- Все HTTP-роуты с `X-Api-Key` используют общий секрет. Отдельная роль администратора в API не реализована, поэтому создание промокодов, просмотр списка промокодов и управление тарифами фактически не отделены от остальных защищённых методов.
- `GET /subscriptions/{subscription_id}` и `POST /payments/invoices/{invoice_id}/cancel` принимают только внутренний ID объекта и не проверяют его принадлежность query-пользователю. Не передавайте эти ID клиенту, которому нельзя доверять, без серверного контроля доступа.
- `POST /payments/invoices/{invoice_id}/cancel` возвращает `204`, даже если счёт не найден или уже не ожидает оплаты.
- `GET /promocodes` и `GET /promocodes/{code}` раскрывают промокоды любому клиенту, располагающему общим `X-Api-Key`.
- WebSocket-менеджер сейчас принимает одно bot connection на процесс. Сообщения доставки переживают рестарт благодаря `AdvertisementDelivery`, но событие может быть отправлено повторно после таймаута ACK; бот обязан дедуплицировать по `delivery_id`.
- Lava webhook отвечает `200` после передачи payload обработчику; обработчик перехватывает внутренние исключения. Поэтому `200` сам по себе не гарантирует, что подписка была создана. Для статуса оплаты клиенту следует проверять счёт через `GET /payments/invoices/{invoice_id}` и подписку через `/subscriptions/active`.
- Лимит активных счетов по пользователю и применение промокода проверяются последовательно в приложении, без отдельной блокировки от одновременных запросов.
