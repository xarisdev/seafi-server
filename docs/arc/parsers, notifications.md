# Общее

> **Статус: проектное описание, не реализованный workflow.** В сервере есть определения ORM-моделей `Advertisement` и `AdvertisementDelivery`, но нет активных парсеров, планировщика, очереди обработки, `TaskManager` или сервиса отправки объявлений. Модули этих моделей сейчас также не импортируются приложением при запуске, поэтому их таблицы не попадают в `Base.metadata.create_all()` автоматически. Не используйте описанный ниже pipeline как контракт работающего API.

## Предлагаемый сбор

Ввиду особенностей парсинга предлагается общий сбор информации с последующей фильтрацией под запросы пользователей, чтобы уменьшить сетевую нагрузку. Возможные направления:

1. Агентские объявления — агентства недвижимости и риелторы.
2. Объявления собственников.
3. Объявления из выбранных городов, первоначально из Бишкека.

Интервал запуска, отказоустойчивость и уведомления пока не реализованы и требуют отдельного проектирования.

## Предлагаемая структура

```
Parsers

 ↓

```

## Модель объявления в коде

В `src/models/advertisement.py` определена ORM-модель со следующими полями:

```
Advertisement:
	id:           INT - PK       // Ключ
	ads_id:       TEXT           // Идентификатор объявления у источника
	ads_source:   INT            // EnumAdsSourceId: 1 (OPENL) или 2 (OPENH)
	url:          TEXT           // Ссылка на объявление
	title:        TEXT
	price:        INT | NULL
	city:         TEXT
	type:         TEXT           // rent | sell
	owner:        TEXT | NULL    // agent | owner | any; по умолчанию any
	created_at:   DATETIME       // Дата записи
	last_seen_at: DATETIME       // Дата последнего получения
	
	UNIQUE (ads_id, ads_source)  // constraint uq_id_source
```

Это только определение модели. Сейчас сервер не сохраняет результаты парсеров и не обновляет `last_seen_at` автоматически. Уникальность пары `(ads_id, ads_source)` задана ограничением модели.

`last_seen_at` предусмотрен для возможной будущей проверки актуальности; задача очистки объявлений не реализована.

## Модель доставки в коде

В `src/models/advertisement_delivery.py` описана отдельная ORM-модель для предполагаемого учёта доставок:

Модель:

```
id:         PK
ads_id:     INT FK(Advertisement.id)
user_id:    INT FK(User.id)
status:     pending | sent | failed
attempts:   INT
sent_at:    DATETIME
created_at: DATETIME

	UNIQUE (ads_id, user_id)
```

В таблице модели поле `ads_id` является FK на `advertisements.id` (внутренний ID записи), `user_id` — FK на пользователя. Поля `attempts` и `sent_at` хранятся в модели; `sent_at` допускает `null`.

Обработка статусов, отправка через WebSocket или Telegram, подтверждение доставки и повторы в текущем коде отсутствуют. Лимит в пять попыток из прежнего проектного описания не является действующим правилом.
